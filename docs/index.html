01 / Architecture

L'architecture médaillon organise les données en trois couches : les données brutes sont stockées en zone Bronze, les données nettoyées et structurées en zone Silver, les données agrégées préparées pour l'analyse en zone Gold.

BRONZEZone de stockage brut

Conserver les données collectées

La zone Bronze constitue le point d'entrée des données dans la plateforme et conserve les éléments issus de la collecte.

  • Extraction depuis les sources web
  • Conservation des données brutes
  • Organisation par compétition et saison
JSON · HTML
SILVERZone de transformation

Structurer les données

Les données sont nettoyées et structurées afin de les rendre cohérentes et réutilisables.

  • Nettoyage et normalisation
  • Structuration des entités
  • Préparation des données métier
JSON
GOLDZone analytique

Préparer les données analytiques

La couche Gold rassemble les transformations et agrégations nécessaires à l'exploitation des statistiques individuelles.

  • Modélisation des statistiques
  • Jeux de données agrégés
  • Préparation pour l'analyse
Parquet · JSON · CSV

03 / ORCHESTRATION

L’orchestration du pipeline est assurée par Apache Airflow. Un DAG est déployé pour chaque saison de chaque compétition. Tous reprennent la même structure générique, avec des paramètres propres à chacun (compétition et saison).

06 / Engineering practices

Le dépôt facilite l'exécution locale et la validation du projet grâce à Docker, aux tests Python, aux contrôles Ruff et aux vérifications automatisées de la CI. Ces pratiques contribuent à rendre les traitements plus faciles à maintenir et à vérifier.

Exécution avec Docker

L'environnement conteneurisé permet de construire l'image du projet et de lancer Airflow en mode standalone. Les données locales sont persistées dans un volume monté. 

docker build -t rugby-data .

mkdir -p data

docker run --rm -p 8080:8080 \
  -e AIRFLOW_VAR_ENV=DEV \
  -v "$PWD/data:/Volumes/rugby_data" \
  rugby-data airflow standalone

L'interface Airflow est accessible sur http://localhost:8080. Les chemins de données du projet sont configurés à partir de /Volumes/rugby_data.

Contrôles automatisés

Des vérifications sont intégrées au dépôt afin de contrôler le code Python, les modèles dbt et le démarrage des composants principaux.

  • Ruff pour les vérifications statiques
  • pytest pour les tests Python
  • dbt parse pour valider les modèles
  • Smoke test Docker sans accès réseau

Data sources & usage

Le code du pipeline, pas les données sources.

Ce projet de portfolio contient le code du pipeline, pas les jeux de données extraits. Les données collectées restent la propriété de leurs sources, notamment RugbyPass et AllRugby.

Le rapport Power BI présente des statistiques à titre de démonstration personnelle et non commerciale. Cette page en montre un aperçu visuel public ; l'accès interactif au rapport reste restreint et les jeux de données bruts ne sont pas publiés.

Toute collecte ou réutilisation doit respecter les conditions d'utilisation des sites concernés et les droits applicables. Ce dépôt n'est ni une API de données ni une autorisation de redistribuer leurs contenus.
